# RNP_WildBerries: ежедневный РНП по Wildberries в Google Sheets

Скрипты на Python, которые каждый день забирают данные из API Wildberries и заполняют в Google Sheets таблицу **РНП** («рука на пульсе»: ежедневная сводка ключевых показателей) по каждому артикулу: заказы, продажи, воронку, рекламу, остатки, затраты и маржу. Раньше такую таблицу собирали вручную; теперь она заполняется автоматически.

> Проект обезличен: идентификаторы таблицы, токены и названия клиента удалены. Публикуется с разрешения заказчика.

## Что собирается

За выбранную дату по каждому артикулу (nmID) считаются и записываются в лист «Все артикулы API»:

- **заказы и продажи:** штуки и рубли до и после СПП, отмены, возвраты, цена, скидка, средний чек, средний СПП;
- **воронка:** переходы, корзины, конверсии в корзину и заказ, процент выкупа;
- **реклама:** просмотры, клики, CTR, расходы, CPC, корзины и заказы из рекламы, ДРР к рекламным заказам, ко всем заказам и к продажам;
- **остатки:** на складах, к клиенту, от клиента, число складов;
- **затраты:** логистика, платное хранение, комиссия, штрафы, себестоимость (из справочного листа);
- **итог:** маржа в рублях и процентах.

Сырые данные (заказы, продажи, воронка, рекламная статистика, списания по рекламе) дополнительно дописываются на отдельные листы `orders`, `sales`, `analyticsHistory`, `A_S`, `AdvertExpenses` для проверки и сверки.

## Как работает

```
WB API (Statistics, Seller Analytics, Advert, Finance)
        │
        ▼
 wb_daily_update  ──►  wb_new_fetches (остатки, финансовый отчёт, платное хранение)
        │
        ▼
 write_all_articles (агрегация по артикулам)  ──►  Google Sheets
```

| Файл | Назначение |
|---|---|
| `wb_daily_update` | главный скрипт: забирает заказы, продажи, воронку, рекламу и списания, пишет сырые листы |
| `wb_new_fetches` | остатки, финансовый отчёт (логистика, комиссия, штрафы), отчёт о платном хранении |
| `write_all_articles` | агрегирует данные по артикулам и записывает метрики в нужные ячейки блоков каждого товара и даты |

Структура листа «Все артикулы API» не зашита по номерам строк: скрипт сам находит блоки товаров по метке «артикул WB» и колонку нужной даты, поэтому таблицу можно расширять.

## Лимиты WB и надёжность

- Воронка продаж: максимум **20 артикулов за запрос** и около 3 запросов в минуту, поэтому между пачками пауза 21 секунда.
- Статистика рекламных кампаний запрашивается пачками по **50 кампаний** с паузой 3 секунды между ними.
- При ответе **429** скрипт ждёт 20 секунд и повторяет запрос (до 5 попыток); у каждого запроса есть таймаут.
- Режим `DRY_RUN` позволяет посчитать данные и показать их без записи в таблицу.
- Отчёт о платном хранении формируется асинхронно: скрипт опрашивает его готовность (до 2 минут).

## Настройка

Секреты и параметры берутся из переменных окружения (файл `.env`), в репозитории их нет:

| Переменная | Назначение |
|---|---|
| `WB_TOKEN_1` | токен WB (статистика) |
| `WB_ADVERT_TOKEN`, `WB_ANALYTICS_TOKEN`, `WB_FINANCE_TOKEN` | отдельные токены для рекламы, аналитики, финансов (если не заданы, берётся `WB_TOKEN_1`) |
| `SPREADSHEET_ID` | идентификатор Google-таблицы |
| `GOOGLE_SERVICE_ACCOUNT_FILE` | путь к файлу сервисного аккаунта |

Таблице нужен доступ у сервисного аккаунта (редактор). Лист «Шаблон для загрузки» хранит себестоимость и комиссию по артикулам.

## Запуск

```bash
pip install requests python-dotenv gspread google-auth
python wb_daily_update.py                  # за дату по умолчанию (по МСК)
python wb_daily_update.py --date 2026-10-01
```

В репозитории файлы названы с суффиксом `_cln` (обезличенные копии). Для запуска переименуйте их так, как они импортируются друг в друга: `wb_daily_update.py`, `wb_new_fetches.py`, `write_all_articles.py`.

Запускать удобно раз в сутки по расписанию (cron, Планировщик заданий Windows).
